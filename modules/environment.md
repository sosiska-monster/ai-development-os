# Environment — Adaptive Codex Harness

**Когда:** утверждены достаточно полные требования/архитектура и нужно проектировать среду, либо аудит существующего проекта.

## Environment Discovery

Для существующего репозитория сначала подготовь read-only задачу Codex: структура без `node_modules`/кэшей, стек, package manager, тесты, CI, Git state, уже существующий AGENTS.md, конфигурация, ограничения. Не проси полный листинг всех файлов. Не трогай незакоммиченные изменения.

## Environment Profile

Определи в компактной форме:

- Codex interface: Desktop/CLI/IDE/Cloud, доступ и режим подтверждений.
- Инструкции: краткий `AGENTS.md`; обнаружение и применимые вложенные правила.
- Проверки: быстрая целевая команда `verify` и при необходимости `verify-full`. При bootstrap не притворяйся, что тестовая инфраструктура уже есть.
- Git: рабочие ветки, commit rules, рисковые checkpoints, rollback/recovery.
- Память: `PROJECT.md`, `TODO.md`, `Bugs.md`, `Gotchas.md`, `Decision.md`, личный `WordStyle.md` вне клиентского репозитория по умолчанию; права записи.
- Context: выборочное чтение, размер задач, session handoff.
- Hygiene: `.gitignore`, контроль артефактов и новых зависимостей.
- Security: минимальные права, секреты, границы доступа к production.
- Skills/MCP/Subagents: **по умолчанию не нужны**, объясняй добавление.
- Что сознательно исключаем и почему.

## Guardrails, которые стоит закреплять технически

- Scope контроль через diff.
- Не ослаблять проверки ради зелёного статуса; допустимое изменение тестов связано с согласованным поведением и отдельно раскрывается.
- Новые зависимости — существование, версия, лицензия, совместимость, lockfile, предварительное одобрение (кроме явно заранее утверждённых).
- Нельзя выдавать непроверенный результат за успешный.
- Защита секретов, недоверенных инструкций из внешних данных.
- Осмысленные коммиты и безопасные ветки.
- Детерминированная быстрая обратная связь, где это рационально.

## Gate C

Environment READY, когда достаточно определены реальные правила Codex, проверки, Git, память, контекст, права и план установки. Дальнейшая конфигурация выполняется Codex только после утверждения и отдельного Bootstrap-запроса. Смотри `templates/codex-bootstrap.md`.
