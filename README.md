# AI Development OS — GitHub instruction library

**Назначение:** версионируемая библиотека методик для **ChatGPT Web (архитектор)**, который помогает готовить и курировать **Codex Desktop (исполнитель)** под любой программный проект. Это **не** репозиторий приложения заказчика.

## Быстрый старт

1. Подключи этот GitHub-репозиторий к ChatGPT, если он приватный и выбранный режим поддерживает GitHub. Передай ChatGPT ссылку на репозиторий и стартовое сообщение ниже.
2. ChatGPT читает `MANIFEST.md` и `CORE.md`, затем выбирает только необходимые модули под задачу.
3. После выяснения требований и согласования архитектуры ChatGPT предлагает **Environment Profile**, а после отдельного запроса — **проектный Codex Bootstrap**. До утверждения допустим ограниченный read-only аудит существующего репозитория через Codex.
4. Codex исследует реальную папку **проекта**, предлагает настройки и создаёт в **проектном** репозитории `AGENTS.md`, рабочую память и проверки — только в рамках согласованного плана.
5. Рабочий цикл: Task → Codex → Evidence Report → ChatGPT Review → Memory / Git → следующий этап.

## Стартовое сообщение в ChatGPT Web

> Ты мой инженерный архитектор в ChatGPT Web; программирование выполняет Codex Desktop. Библиотека нашего процесса: **[вставь URL данного GitHub-репозитория]**. Прочитай `MANIFEST.md` и `CORE.md` в выбранной версии; назови фактически прочитанную версию и файлы. Выбирай последующие модули по задаче, а не читай всю библиотеку подряд. Если доступ к GitHub невозможен, скажи это прямо. Сначала определи, у нас новый проект, ТЗ клиента или существующий репозиторий. Кодекс-бутстрап генерируй только после согласования архитектуры и среды и моего отдельного запроса.

## Карта

- [`MANIFEST.md`](MANIFEST.md) — индекс и правила маршрутизации.
- [`CORE.md`](CORE.md) — короткое постоянное ядро для ChatGPT Web.
- [`modules/`](modules/) — специфические методики, читаются по необходимости.
- [`templates/`](templates/) — формы передачи задач и доказательств.
- [`RATIONALE.md`](RATIONALE.md) — **почему библиотека устроена именно так**; антиграбли при изменении самой методологии.
- [`MAINTENANCE.md`](MAINTENANCE.md) — правила безопасной эволюции библиотеки.
- [`CHANGELOG.md`](CHANGELOG.md) — изменения версий.

## Разделение репозиториев

**Библиотека AI Development OS:** общие процедуры, причины решений, шаблоны. Никаких приватных ТЗ клиентов, секретов, персональных настроек и исходного кода заказчиков.

**Репозиторий продукта:** исходники, проектный `AGENTS.md`, проверки, актуальная память (`PROJECT.md`, `TODO.md`, `Bugs.md`, `Gotchas.md`, `Decision.md`). Индивидуальный `WordStyle.md` по умолчанию хранится в личном пространстве, а не в репозитории клиента.

## Ограничения доступа

Ссылка сама по себе не гарантирует, что ChatGPT сможет прочитать файлы. Для приватного репозитория требуется разрешённый доступ через подключённый GitHub или иное доступное средство; доступность зависит от текущего режима ChatGPT. При недоступном подключении приложи нужные файлы вручную. ChatGPT не должен утверждать, что прочитал то, чего не видел.

## Версионирование

Стабильные версии закрепляй Git-тегом `vX.Y.Z`. Для текущих проектов сохраняй в Environment Profile конкретную версию библиотеки. Обновления методики применяй после оценки изменений, а не бесконтрольно с движущейся ветки `main`.
